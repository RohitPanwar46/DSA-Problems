# Time complexity order (batter - worst)

### O(1) → same time always (best)

### O(log n) → grows very slowly (excellent)

### O(n) → grows normally (acceptable)

### O(n log n) → still efficient (used in merge/quick sort)

### O(n²) and above → dangerous for large data

### O(2ⁿ), O(n!) → only for small inputs or brute force
